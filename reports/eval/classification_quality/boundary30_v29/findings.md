# 이번 실행의 결론

**추출 조건식을 단순 추가하는 방식은 이번 개발 표본에서 채택하지 않는다.**

| 항목 | 코드만 | 코드 + 추출 조건식 |
|---|---:|---:|
| 계약 일치 | 21/30 (70%) | 15/30 (50%) |
| macro-F1 | 0.7905 | 0.6800 |
| 복합 조건 16건을 구체 라벨로 축약 | 7/16 | 13/16 |
| 출력 오류 / 최종 근거 필드 오류 | 0 / 0 | 0 / 0 |

조건식 추가로 정답에서 오답으로 바뀐 사례 6건, 오답에서 정답으로 바뀐 사례 0건이다. 그룹 AND 역할을 그룹만으로, 소유자 AND 관리자를 소유자 OR 관리자로 선택한 사례가 포함된다. 추출식은 1,920개 진리표 검사에서 원본 함수·계약과 일치했다. 최종 evidence_invalid=0은 입력 참조 형식 검증일 뿐 조건 의미가 맞다는 뜻이 아니다.

이번 결과는 템플릿 15개×표현 2종의 합성 개발 표본에서 각 조건 1회 실행한 결과다. 더 넓은 데이터에서 조건식이 항상 해롭다는 결론은 아니다. 코드만 조건 역시 오류 9건이 남아 운영 적용 기준을 충족했다고 볼 수 없다.

다음 후보는 최종 라벨을 LLM이 선택하는 구조를 유지하면서 **누락된 필수 조건을 탐지해 자동 적용을 차단하는 검증기**를 별도로 평가하는 것이다. 원시 모델 라벨은 보존하고 적용 가능 여부만 구분해야 한다. 이번 실행에서 해당 검증기나 런타임은 변경하지 않았다.

총 API 응답 61회(기본 60개 예측 + 재요청 1회), 실제 사용량 입력 84,445토큰·출력 3,761토큰. 기존 v2.9 프롬프트·고정 test·학습 데이터는 보존했다. 관련 단위 테스트 9개 통과.
