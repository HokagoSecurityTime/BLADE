v2.9 고정 · 새 외부 프로젝트 OAS/코드 비교

새 프로젝트 1개, 엔드포인트 23개를 두 입력 조건으로 실행했다. 분류 결과와 적용 검증 결과를 분리했다. 고정 검증기는 외부 코드·바인딩을 지원하지 않아 23/23건 평가 불가이며, 모두 적용 보류다. 이는 위험 탐지 성공률 100%를 뜻하지 않는다.

출처: fastapi/full-stack-fastapi-template. 이전 실험 수집 manifest/스크립트 검색에서 이 프로젝트 사용 기록이 없었다. 같은 프레임워크 일반화 검증이며, 다중 프로젝트·6종 전체 평가가 아니다.

고정 조건

v2.9 프롬프트·application_guard.py 해시는 수집 전에 protocol.json에 고정했다. 모델 gpt-4o-mini, temperature 0, seed 42, 조건별 1회, 동시 요청 4개다. 대상 ID·입력·에이전트 참조 라벨은 API 실행 전에 해시로 고정했다. 조건별 ID는 같다. 원시 응답과 원래 라벨을 보존했다.

저장소에 OpenAPI 파일이 없어 라우트 선언·docstring·응답 필드로 만든 정적 OAS 투영본을 사용했다. 실제 서버 export와 동일하다고 주장하지 않는다. 타입/본문 스키마는 완전하지 않다. 익명 경로에 임의 security: []를 추가하지 않았으며, 인증 없는 경로의 security_state는 unknown이다. 코드 조건에는 실제 핸들러·참조 함수·모델·라우터 등록과 전역 middleware를 추가했다. 정답·검수 설명·테스트 코드는 모델 입력에 넣지 않았다. private 경로 1개는 개발 환경 전용임을 기록했다.

외부 비교 실험 최종 해석

결과

새 프로젝트 fastapi/full-stack-fastapi-template의 23개 엔드포인트를 같은 ID로 비교했다. 참조 라벨이 있는 19건에서 OAS 정적 투영본은 7/19(36.8%), OAS+코드는 15/19(78.9%) 일치했다. support가 있는 5종 macro-F1은 0.3091 → 0.6921이다. 7종 평균은 0.2208 → 0.4943이다.

이는 API 실행 전에 에이전트가 작성한 소스 검토 참조와의 일치율이다. 독립적인 사람 정답 정확도나 의도된 정책의 검증 완료를 뜻하지 않는다. 미확정 4건은 정답 보류로 대체하지 않고 점수 분모에서 제외했다. tenant와 그룹 membership 정답 사례가 없어 두 패턴의 성능은 아직 평가하지 못했다.

코드가 있어도 남은 불일치 4건

검증기는 아직 외부 적용 불가

고정 검증기의 외부 코드/바인딩 평가 가능 건수는 0/23이다. 두 조건 모두 전부 적용 보류다. 올바른 구체 제안도 OAS 7/7, OAS+코드 15/15 보류됐다. 지원 표본의 오차단율은 N/A이고, 운영상 올바른 제안의 적용 보류율은 100%다.

metrics.json의 independently_confirmed_unsafe=0은 별도로 검사한 item 조회·수정·삭제와 user-by-id 네 경계에서만의 수치다. 전체 23건에 위험한 예측이 없다는 뜻이 아니다. 위 자기 삭제·관리자 삭제 불일치는 그 네 경계 밖에 있다. 위험 사례가 없는 제한된 감사 분모에서 검출률은 N/A이며, 모든 건을 보류했다는 사실을 위험 탐지 성공으로 계산하지 않는다.

실행과 재현

  • API 응답 47회: 최종 예측 46건(23 × 2), 근거 인용 교정 요청 포함. 입력 87,862 / 출력 3,494토큰.
  • 원본 함수·인가 의존성 로컬 검사 22건 통과. DB/사용자 객체 대역을 사용하며 실제 서버·JWT·PostgreSQL 통합 테스트가 아니다.
  • 관련 pytest 27개 통과. 모델 원래 라벨과 원시 응답 보존.
  • 프롬프트·검증기는 수집 전 해시 고정. 입력·참조는 API 실행 전에 고정. preparation_initial/, preparation_precheck/는 API 실행 전 수집 코드 검사 중 보존한 초안이며 실행에 사용한 입력이 아니다. 실제 입력은 execution_manifest.json의 해시로 식별한다.
  • 기존 frozen test 253건 해시 유지. 런타임·학습 데이터·프롬프트·검증기 변경 없음.

다음 개발 과제

코드 제공은 도움이 됐지만, 현재 검증기는 실서비스 입력을 해석하지 못한다. 다음은 외부 핸들러→인가 함수→객체 조회를 연결하고 조건을 보존하는 어댑터 개발이다. 특히 NOT superuser와 target != caller 같은 부정 조건을 버리면 안 된다. CurrentUser를 그룹 membership으로 바꾸지 않는 바인딩 검증도 필요하다.

이번 프로젝트를 어댑터 개발에 사용하면 이후에는 개발셋으로 취급한다. 어댑터 버전을 고정한 뒤 다른 프로젝트에서 평가해야 한다. 현재 결과만으로 자동 정책 적용이나 6종 전체 성능을 주장할 수 없다.
