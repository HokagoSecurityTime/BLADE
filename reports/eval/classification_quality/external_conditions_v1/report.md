# 새 외부 프로젝트 조건 추출 검증

기존 합성 14/14를 외부 성능으로 일반화할 수 없다는 점을 확인했다. 고정 추출기는 새 프로젝트 3개 라우트를 모두 지원하지 못했다.

출처: https://github.com/nsidnev/fastapi-realworld-example-app/tree/029eb7781c60d5f563ee8990a0cbfb79b244538c

| 항목 | 결과 |
|---|---|
| 기존 추출기 지원 | 0/3 라우트 |
| 라우트→권한 의존성→서비스 비교 연결 | 3/3 확인 |
| 실제 원본 비교 함수 단위 검사 | 12/12 통과 |
| 서로 다른 비교 함수 | 2개 (article·comment) |
| 전체 서버·DB·상위 테스트 실행 | 미실행 |
| 최종 엔드포인트 정답 | 미확정 |

## 확인한 근거

PUT article·DELETE article·DELETE comment는 데코레이터 Depends에서 권한 검사로 연결된다. 검사는 작성자 username과 요청자 username의 동일성을 검사하는 원본 함수가 false이면 403을 발생시킨다. 같은 커밋의 상위 테스트에도 타인 수정·삭제 거부가 명시돼 있다.

원본 파일은 수정하지 않았다. 단위 실행은 import·annotation·기본값 실행을 제외하고, 호출이 없는 단일 속성 비교 return 본문만 검증 후 실행했다. 객체는 SimpleNamespace 대역이다. 따라서 JWT·DB·HTTP 요청 전체를 검증한 결과가 아니다. 12개 검사는 3개 라우트×4개 입력이며 article 비교 함수는 두 라우트에서 공유하므로 독립 12개 정책 사례가 아니다.

## 지원하지 못한 원인과 다음 구현 범위

기존 추출기는 동기 함수, 함수 인자 Depends, sub/owner 딕셔너리 비교만 제한적으로 처리했다. 새 소스는 async 라우트, 데코레이터 dependencies, 별도 모듈 함수, author.username 속성 비교를 사용한다. 우선 이 연결을 별도 어댑터로 다뤄야 하며, 이름만 owner_match로 치환하면 안 된다. 이번 탐색의 조건 후보와 기존 추출기 예측은 분리했다. 아직 범용 추출기 지원 확장이나 LLM 정확도 개선을 입증한 것은 아니다.

이 외부 사례는 owner 계열에 한정된다. tenant·membership 등 나머지 유형의 외부 검증은 남아 있다. 런타임·기존 프롬프트·고정 test는 변경하지 않았다.
