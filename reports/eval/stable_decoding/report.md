### 4.2 내용

- **잘림(84건)**: 스키마 제약 덕에 모두 `{"label": "...", "confidence": ..., "rationale": "` 까지는 올바르게 나왔고 rationale 문자열이 닫히지 않은 채 256 토큰에 도달했다. 84건 전부 label 필드가 존재한다(enum 값). 다만 채점은 기존 run과 같은 parse()(완전한 JSON만 인정)를 그대로 써서 비교 가능성을 유지했고, 잘린 건의 label을 구제해 채점하지 않았다.
- rationale이 길어진 양상은 두 가지다. (a) 영어·한국어 설명이 끝없이 이어짐(v2 oas_code 56건 중 55건, 예: `240a92b7ee284506eb3f` "Intentionally anonymous reference catalogue lookup; no authentication ... The operation is read-only and returns a fixed string, so there are no secrets ..."). (b) 한국어로 시작하다 중국어로 새어 무관한 문장을 이어감(v4 5건·v3b 4건·v2 1건, 예: `bcfa59eea899fc11ba4f`, supp `v4t-chatwoot-90bab44d61`). 기본 디코딩에서는 같은 행이 200~250자짜리 정상 JSON이었다.
- 추정 원인: repetition_penalty 1.1이 이미 여러 번 쓰인 `"`·`}` 같은 구조 토큰과 앞서 쓴 한국어 토큰을 함께 깎아, 문자열을 닫는 대신 새 어휘(다른 언어 포함)로 이어가게 만든다. 스키마 제약은 구조는 지키지만 문자열 길이를 제한하지 않으므로 이를 막지 못한다. 두 변경을 함께 적용했기 때문에 이 실험만으로는 분리 확인이 안 된다.
- **조기 종료(26건)**: base oas 25건은 `"rationale":"フィールド: 実際の根拠` 뒤에 공백·탭이 이어지다 27~28 토큰에서 생성이 끝났다. v4 s44 oas_code 1건(`32447425974cf6f24467`)은 45 토큰에서 문자열 중간에 끝났다. 어느 쪽도 JSON이 닫히지 않았다. 제약기 상태(연속 공백 한도 12 등)와 생성 종료의 상호작용으로 보이나 기록된 출력(특수 토큰 제거 후 디코딩)만으로는 종료 토큰을 확인할 수 없어 원인은 미확정이다.
- 기본 디코딩 base의 오류 140건은 대부분 JSON 밖 자유 텍스트·label 비표준값이었고 안정화에서 28건으로 줄었다. supp oas_code에서 base가 64건 잘렸던 것도 3건으로 줄었다.

## 5. 해석

1. 스키마 제약은 형식 오류를 거의 없앴다. 안정화의 오류는 사실상 전부 "rationale이 끝나지 않음"이며, 그중 84/110건은 label이 이미 유효하게 나와 있다.
2. 그 대신 반복 억제가 긴 생성을 유발했고(v2 oas_code 56건), 구체 정밀도가 모든 LoRA에서 1 std 이상 떨어졌다. 정밀도 하락은 두 경로가 겹친 결과다. (a) 기본 디코딩에서 출력 오류로 빠졌던 행이 구체 label로 답하면서 오답도 함께 늘었다(supp에서 정확도가 오른 것과 같은 현상의 뒷면). (b) 반복 억제가 label 선택 자체도 바꿨다. v4 oas_code 합성 제외(정답이 구체인 206건)에서 구체로 답한 수는 seed별 142/127/156 → 146/133/156으로 조금 늘고, 그중 정답 수는 119/100/126 → 116/99/124로 조금 줄었다.
3. supp(실제 프로젝트 코드)에서는 정확도·macro-F1이 올랐지만, 사전 기준은 test_v30 oas_code 구체 정밀도를 조건으로 두었고 그 조건을 모든 모델이 미달하므로 채택하지 않는다. 기준을 사후에 바꾸지 않는다.
