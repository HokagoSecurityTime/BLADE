# 소유권 처리 방식 DB 통합 실험

FastAPI ASGI 요청과 실제 임시 SQLite 파일을 사용한 통합 테스트 8개 통과. 외부 API 호출·모델 학습 없음. 고정 test 데이터나 공개 취약 API를 실행하지 않았다.

| 검증 대상 | 결과 |
|---|---|
| 생성 시 검증된 JWT sub를 소유자로 저장 | DB 직접 조회로 확인 |
| 타인 객체 ID 조회·수정 | 404, 기존 저장값 유지 |
| 타인·null·빈 문자열·SQL 형태 소유자 지정 | 403, 저장 행 0건 |
| 소유자 변경 시도 | 403, DB 소유자 유지 |
| 자기 프로필 조회 | query 및 X-User 값으로 다른 사용자 선택 불가 |
| JWT 누락·서명 위조·만료 | 401 |
| 목록·페이지·전체 건수 | WHERE principal 적용 후 계산, 타인 데이터 제외 |
| 미정의 중첩 body 필드 | 422 |

실험 코드: `training/experiments/ownership_backend.py`

재현: `.python/python.exe -m pytest tests/test_ownership_backend_experiment.py -q`

## 확인한 점

의미 라벨과 집행 방식을 분리하는 접근은 DB 저장·조회까지 구현할 수 있다. 생성 시 소유자 지정, JWT 주체로 자기 리소스 선택, 목록 쿼리 제한은 백엔드가 수행해야 하는 동작이다. 객체 ID 조회와 수정은 소유 조건을 같은 SQL 문에 넣었다.

## 적용 범위

- 개발 서비스는 운영 BLADE와 분리되어 있다. 런타임·정책 스키마를 수정하거나 보류 검증을 해제하지 않았다.
- TestClient가 ASGI 요청을 처리하며 외부 포트로 배포하지 않았다. 실제 프록시 경유, 운영 JWT 키 관리, 다른 DB 엔진, 다중 프로세스 동시성은 검증하지 않았다.
- 테스트의 개발용 서명 키는 테스트 fixture에서만 사용한다. 서비스 factory는 키를 호출자가 전달받도록 한다.
- F1 개선 실험이 아니다. 기존 18건을 지원한다고 자동 판정하거나 라벨을 바꾸지 않았다.
- 기존 서비스에 적용하려면 서버 측 어댑터 계약과 정책 스키마 확장을 별도로 검토해야 한다. 현재 런타임 수정 금지 규약 아래에서는 제품 적용을 하지 않는다.
