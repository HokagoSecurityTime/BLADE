## 확인 내용

- 데모 OpenAPI에서 7개 메서드·경로와 `{orderId}` 파라미터 추출.
- 데모 DDL에서 `orders.owner_col == "user_id"`, FK 대상 `users.id` 확인.
- `users.tenant_col == "org_id"`, `orgs.tenant_col == "id"`로 조직 테이블 식별.
- JSON/YAML 입력, 경로 수준·operation 수준 파라미터 병합과 중복 제거.
- operation ID, tags, summary 추출 및 생략 시 기본값.
- 내부 JSON Pointer 참조와 이스케이프 처리; 외부·순환·없는 참조 거부.
- 컬럼명 휴리스틱 우선순위 및 users/orgs FK를 이용한 후보 보완.
- 인라인·테이블 제약 PK/FK, 복합 키, 스키마 한정 이름, 따옴표 식별자.
- 주석, 문자열 내부 쉼표와 SQL 키워드, 중첩 괄호가 있는 타입·기본값 처리.
- 구버전 OAS, 미지원 SQL 문, 닫히지 않은 괄호와 존재하지 않는 키 컬럼 거부.

## 인터페이스와 범위

- [oas.py](../pipeline/parsers/oas.py): `parse_oas(document: str) -> list[Endpoint]`.
  파일 내용인 JSON/YAML 문자열을 받습니다. 파서용 Endpoint는 기존 정책 스키마와 별도입니다.
- [erd.py](../pipeline/parsers/erd.py): `parse_erd(ddl: str) -> dict[str, TableInfo]`.
  SQL은 실행하지 않습니다. 파일 읽기와 외부 호출도 하지 않습니다.
- `TableInfo.pk`와 `columns`는 순서 있는 컬럼명 목록입니다.
  `fks`는 `ForeignKey(columns, ref_table, ref_columns)` 목록입니다.
- 명시한 컬럼명 휴리스틱을 우선하며, 이후 단일 컬럼 FK를 선언 순서대로 후보에 포함합니다.
  orgs 등 조직 테이블은 단일 PK를 `tenant_col`로 사용합니다.
  복합 PK/FK를 단일 소유자·조직 컬럼으로 임의 축약하지 않습니다.
- ERD 파서는 일반적인 `CREATE TABLE [IF NOT EXISTS]` 선언을 지원합니다.
  `ALTER TABLE`, 방언별 테이블 옵션 등은 지원하지 않으며 오류를 반환합니다.
  전체 SQL 문법 검증기는 아닙니다.
