# Compose·7단계 데모 통합 — 2026-09-09

## 상태

Compose와 데모 스크립트를 구현했다. **Docker 클린 환경 검증은 미실행**이다.
현재 Windows PC에서 docker와 bash 실행 파일을 찾지 못했고,
`wsl --list --quiet`도 WSL 미설치를 보고했다. Docker 설치/재부팅은 수행하지 않았다.
따라서 아래 로컬 결과를 컨테이너 통합 성공으로 간주하지 않는다.

## 구성

- Dockerfile: Python 3.11, 프로젝트 의존성 설치. 비밀 파일·로컬 DB·설치 파일은 빌드 컨텍스트에서 제외.
- Compose: demo-backend 9000, admin-api 8100, proxy 8080.
- proxy는 demo-backend/admin-api healthcheck 통과 후 시작한다.
- demo-data를 백엔드는 쓰기 가능, 프록시는 읽기 전용으로 마운트한다.
- admin-data에 정책 SQLite/YAML/탐지 JSONL을 보관한다.
- `.env`를 사용한다. 프록시에는 필요한 런타임 변수만 전달한다.
- `scripts/demo.sh`는 admin-api 컨테이너에서 `scripts/demo.py`를 실행한다. 호스트 Python/curl/jq 없이 동작하도록 구성했다.
- 실제 데모 `/generate`는 실제 LLM을 호출한다. 정답 라벨로 강제 교체하지 않는다.
- 빈 정책 저장소를 요구하며 기존 정책을 삭제하지 않는다.

## 로컬 검증

`tests/test_compose_demo.py`는 실제 demo/admin HTTP 서버와 프록시, 임시 SQLite를 사용한다.
분류기만 저장된 Ollama 응답으로 대체하고, 데모 스크립트와 동일한 `run()`을 실행했다.
정책 approve/rollback과 탐지 조회는 실제 HTTP이며 SQLite 행 유지는 직접 SELECT로 확인했다.

```text
.python/python.exe -m pytest tests/test_compose_demo.py -q -s
[1/7] PASS POST /generate: 7 PENDING policies
[2/7] PASS All 7 policies approved
[3/7] PASS user_99 GET: 403; approve hot reload 0.359s <= 0.5s
[4/7] PASS user_77 GET: 200
[5/7] PASS user_99 DELETE: 403; SQLite confirms order 1042 still belongs to user_77
[6/7] PASS GET /detections: both demo requests have BLOCK records
[7/7] PASS Rollback: user_99 GET 200 + OBSERVE/no_policy; 0.391s <= 0.5s
2 passed in 2.81s
```

구조화된 결과: [compose-demo-local.json](compose-demo-local.json).
BLOCK 2건은 조회·삭제 요청 ID로 연결해 확인한다. 핫리로드 확인 중 발생하는 재시도 로그와 혼동하지 않는다.
반영 시간은 관리 API 응답 수신부터 프록시의 변경된 응답 수신까지 측정한다.

전체 회귀:

```text
BLADE_LLM_PROVIDER 미설정
.python/python.exe -m pytest -q
125 passed, 1 skipped, 2 warnings in 6.71s
```

skip은 실제 LLM 테스트, 경고는 기존 Starlette/AnyIO deprecation이다. 이미지 자료는 없다.

## 남은 필수 검증

Docker Compose v2와 Bash가 있는 환경에서 유효한 `.env`/LLM을 준비한 후:

```bash
docker compose up -d && bash scripts/demo.sh
```

이미지 빌드, 컨테이너 서비스 간 통신, 볼륨 읽기 전용 동작, 실제 LLM 결과를 포함한
7단계 성공 여부는 위 실행으로 확인해야 한다. 현재 문서는 그 성공을 주장하지 않는다.
